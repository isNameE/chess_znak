# Контур сборки — демо АРМ агрегации

Версия 0.2: один общий стол для двух линий розлива, сенсорный интерфейс, FastAPI и собственная PostgreSQL. Это демонстрационная программа для согласования процесса. Исходные документы «Этапы» заменены уточнениями из нового ТЗ; оставшиеся вопросы перечислены в [архитектуре](docs/architecture.md).

## Возможности

- Выбор исходной линии, продукции и партии. Рецепты: 15 бутылок по 1 л, 3 по 5 л, 50 коробов в паллете; значения настраиваются.
- Имитатор группового чтения, ручной ввод тестовых кодов, запрет дублей и неподходящей продукции, изменение незавершённого состава.
- Сохранение конкретного состава коробов и паллет, реестр, поиск по вложенному коду, линии и партии.
- Атомарное создание упаковки, документа обмена, задания печати и события. Отдельная текстовая этикетка с печатью через браузер/PDF; идентификатор при повторной печати сохраняется.
- Очередь имитатора ГИС МТ: принятие, отказ, потеря связи, тайм-аут и уточнение результата. Сначала документы коробов, затем паллеты.
- PostgreSQL с нормализованными таблицами, миграциями, уникальными ограничениями и внешними ключами. Двойные запросы и устаревшее состояние блокируются.
- Подготовленный адаптер тестового True API: авторизация внешней подписью, запрос сведений о КИ, транспорт подписанного документа и чтение ответа. Доступ и тестовая подпись пока отсутствуют, реальная интеграция не проверена.

## Быстрый запуск на Windows

На серверном компьютере нужны 64-разрядный Python 3.13 и PostgreSQL 18. На сенсорном моноблоке, используемом как клиент, нужны браузер и доступ к серверу; Python и PostgreSQL на клиент устанавливать не требуется. Совместимость браузера с конкретной Windows 10 и удобство сенсора проверяются на устройстве.

Из папки репозитория:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-lock.txt
.venv/Scripts/python.exe scripts/setup_local_postgres.py
.venv/Scripts/python.exe server.py
```

Открыть [локальное демо](http://127.0.0.1:8765). При следующих запусках можно использовать `Запустить демо.cmd`. Окно сервера оставить открытым; Ctrl+C останавливает приложение. Помощник запускает собственный кластер PostgreSQL, если он уже создан.

`setup_local_postgres.py` создаёт отдельный кластер **только** в `data/pg18`, порт 55432, базу и пользователя `arm_demo`. Существующая служба PostgreSQL и базы других программ не изменяются. Пароль генерируется локально, сохраняется в игнорируемом `.env`, подключения к кластеру требуют SCRAM. Кластер слушает только `127.0.0.1`. Пользователь этого локального кластера административный; для заводского сервера ИТ-служба должна разделить учётные записи миграции и приложения.

Если PostgreSQL уже предоставлен ИТ-службой, скопировать `.env.example` в `.env`, настроить `DATABASE_URL` и запускать сервер без помощника локального кластера. Миграции применяются при старте; учётной записи для первого запуска нужны права создания объектов.

## Вариант с Docker

`compose.yaml` поднимает только PostgreSQL, приложение работает в Python. В `.env` задать `POSTGRES_PASSWORD` и соответствующий `DATABASE_URL`. Случайный пароль не должен содержать необработанные спецсимволы URL; при необходимости использовать URL-кодирование.

```powershell
docker compose up -d db
.venv/Scripts/python.exe server.py
```

Порт базы опубликован только на loopback. Не запускать Docker-базу и собственный локальный кластер одновременно на порту 55432.

## Демонстрация

1. Применить линию и номер партии. Выбрать продукцию.
2. Нажать «Считать тестовый набор». Проверить дубль, неверный товар и нечитаемый код.
3. Закрыть короб. Проверить его состав и текстовую этикетку. В диалоге печати можно сохранить PDF.
4. На экране паллеты добавить короб по идентификатору или заполнить паллету тестовыми коробами. Закрыть её.
5. В очереди имитатора проверить отказ и тайм-аут. После тайм-аута повтор запрещён до уточнения. Кнопка обработки очереди обрабатывает только доступные документы; паллета с неразрешённым документом короба остаётся в очереди.
6. В реестре найти короб и паллету по коду бутылки. Обновить страницу и перезапустить сервер: данные сохраняются.
7. Завершить текущую сборку и переключиться на вторую линию. Паллета в этой версии собирается из коробов одной продукции, линии и партии.

Для короткого сценария до сборки можно задать, например, 3 бутылки и 2 короба. Чтобы заполнить совершенно пустую базу полным примером 50/1, выполнить `scripts/seed_demo.py` через Python из `.venv`; скрипт откажется изменять непустую базу.

## Подготовка True API

Открыть экран True API и [инструкцию подключения](docs/true-api.md). По умолчанию адаптер выключен. Нужны тестовый кабинет, права и внешнее средство электронной подписи. Закрытый ключ и PIN программа не запрашивает.

Учебные `DEMO-*` не являются КМ/КИГУ/КИТУ/SSCC и блокируются перед отправкой. Учебная очередь отделена от транспорта True API. Схема JSON, тип документа, товарная группа, пути методов и идентификаторы упаковок должны быть согласованы по актуальной документации участника до отправки. Получение HTTP 200 не означает окончательного принятия документа.

## Размещение для сетевого показа

По умолчанию демо доступно только локально. Для отдельного серверного компьютера настроить `ARM_HOST` на нужный интерфейс, `ARM_ACCESS_USER` и `ARM_ACCESS_PASSWORD`. Использовать HTTPS через обратный прокси с сертификатом, которому доверяет моноблок, и ограничить доступ заводской сетью. PostgreSQL не выставлять в браузерную сеть. Внешний адрес должен сохранять Host и корректную схему при проксировании.

Без настроенных учётных данных сервер откажется слушать сетевой интерфейс. Общий вход рабочего места — ограничение демо; персональные роли и промышленный аудит пользователей ещё не реализованы. Сейчас события подписаны демонстрационной учётной записью.

## Перенос из первой демоверсии

Исходный SQLite открывается только для чтения, не удаляется и не перезаписывается:

```powershell
.venv/Scripts/python.exe migrate_legacy.py data/demo.sqlite3
```

Импорт разрешён только в пустую PostgreSQL-базу. Упаковки, коды, документы, очередь и события сохраняются; старым упаковкам назначаются линия 1 и партия `ПЕРЕНОС-ДЕМО`, поскольку источник в первой версии не учитывался. Повторный импорт в непустую базу блокируется. В рабочей версии SQLite больше не используется.

## Резервное копирование

```powershell
.venv/Scripts/python.exe scripts/backup.py
```

Создаётся custom-format дамп PostgreSQL в игнорируемой папке `backups`. Пароль передаётся дочернему `pg_dump` через окружение, а не аргументы. Для подключения к удалённой БД поддержаны `sslmode` и `sslrootcert` из URL. Для регулярной работы ИТ-службе следует настроить расписание, копирование на другой носитель, контроль выполнения и пробное восстановление.

Восстановление выполнять в **новую отдельную базу** утилитой `pg_restore --no-owner --dbname=NEW_DATABASE backups/FILE.dump` с настроенными локально переменными PGHOST/PGPORT/PGUSER/PGPASSWORD. Сверить число кодов, составов, документов и событий; затем выполнять согласованное переключение. Демо не выполняет автоматического удаления действующей базы.

Для остановки собственного локального кластера после остановки приложения:

```powershell
& 'C:/Program Files/PostgreSQL/18/bin/pg_ctl.exe' -D data/pg18 -m fast -w stop
```

## Проверки и исходники

```powershell
.venv/Scripts/python.exe -m pytest
node --check static/app.js
```

PostgreSQL-тесты создают случайные изолированные схемы `test_arm_*` и удаляют только их. База приложения не очищается. Нужен доступ к тестовой PostgreSQL; на CI поднимается отдельный сервис. True API проверяется через `httpx.MockTransport`, без настоящих токенов и сетевой отправки. `requirements-lock.txt` фиксирует проверенное окружение с тестовыми зависимостями.

- `domain.py` — правила и переходы состояния.
- `repository.py`, `migrations/` — PostgreSQL и миграции.
- `server.py`, `config.py` — HTTP API и настройки; описание API доступно на `/docs`.
- `static/` — лёгкий сенсорный интерфейс.
- `integrations/` — транспорт sandbox, журнал отправок.
- `scripts/` — запуск базы, пример, резервная копия и ИТ-транспорт документа.
- `docs/architecture.md` — схема базы, ограничения и вопросы к ТЗ.

Базы, `.env`, резервные копии, журналы, ключи и сертификаты исключены из Git. Исходники разработанных компонентов находятся в репозитории; сторонние библиотеки распространяются на условиях своих лицензий.

## Границы версии

Физические камера, принтер и сканер ещё не интегрированы. Реальные идентификаторы упаковок, GS1-печать, автоматическая криптоподпись, исправление принятых ГИС МТ агрегатов и трёхлетняя эксплуатационная нагрузка требуют отдельной реализации и испытаний. Заявления о 99% доступности и круглосуточной промышленной готовности эта демоверсия не подтверждает.
